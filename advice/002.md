对，这里应该把问题**收紧**。

不再讨论轨迹、波束形成、多层融合、DRL 等新体系，只回答一个问题：

> **在你现在已经有的“15 UAV + 双站链路 + OTFS-DD + exact LLR + C2F/active acquisition + 单 fusion + 有限 looks/功率/报告预算”框架里，怎样把有限资源真正集中到小 RCS 目标上，让它尽可能被探测出来？**

我认为可以收敛成下面这一条主线。

## 一、现有系统真正的问题：资源虽然很多，但没有形成“救援机制”

现在小 RCS 目标的问题不是“完全没有可用操作”，而是现有操作更多被当成独立 sweep：

- `n_looks` 可以变；
- power scale 可以变；
- Tx/Rx 链路可以选；
- DD refinement 可以开；
- 每目标最多观测数可以调；
- max-min / target priority 可以调；
- fusion / report 可以选。

但这些东西还没有围绕一个明确逻辑组织起来：

先判断谁难→容易目标停止投入→把剩余 sensing resource 转给难目标→为难目标选择最有效的少量观测\boxed{ \text{先判断谁难} \rightarrow \text{容易目标停止投入} \rightarrow \text{把剩余 sensing resource 转给难目标} \rightarrow \text{为难目标选择最有效的少量观测} }

这才应该是“小目标探测”的核心。

------

# 二、不要试图让所有目标都用同一种 sensing mode

这是现在最值得改的地方。

假设标准观测模式：

m0=(P0,L0,r0)m_0=(P_0,L_0,r_0)

例如：

- P=P0P=P_0
- 16 looks
- 普通 DD 处理

不要所有目标统一这样做。

而是允许：

mq∈{mnormal,menhance,mrescue}.m_q\in \{ m_{\rm normal}, m_{\rm enhance}, m_{\rm rescue} \}.

例如非常简单：

| 模式    | looks | 功率 | DD refinement |
| ------- | ----- | ---- | ------------- |
| normal  | 16    | 1.0  | 否            |
| enhance | 64    | 1.0  | 是            |
| rescue  | 144   | 1.25 | 是            |

这里**不是新增系统模块**，这些参数你当前框架已经都有。

关键只是：

> **由算法决定哪个目标值得进入 rescue mode。**

而不是提前固定所有目标都 144 looks。

# 三、第一原则：容易目标一旦够了，就停止继续获取证据

这是小 RCS 能不能被救起来最关键的资源来源。

比如检测要求：

PDreq=0.95.P_D^{\rm req}=0.95.

如果 target 1 已经：

P^D,1=0.98,\widehat P_{D,1}=0.98,

再给它一条 observation，可能变成：

0.980→0.985.0.980\rightarrow0.985.

价值很低。

但 target 7：

0.35→0.550.35\rightarrow0.55

即使绝对 PDP_D 还不够，它的边际价值明显更大。

因此目标函数应该非常明确：

dq=[PDreq−P^D,q]+.d_q= [P_D^{\rm req}-\widehat P_{D,q}]_+.

第一目标：

min⁡max⁡qdq\boxed{ \min \max_q d_q }

也就是**优先抬最差目标**。

然后才考虑：

min⁡∑qdq,\min\sum_qd_q,

最后才是：

min⁡E,min⁡Nreport,min⁡C.\min E,\quad \min N_{\rm report},\quad \min C.

其实你现在 Low-RCS 分支里的 lexicographic master 已经非常接近这个方向。

所以这里没必要重新发明理论。

# 四、第二原则：小目标不是“多选链路”，而是“选真正有效的链路”

现在如果某个小目标很弱，不应该简单：

> K=3 不行 → K=5 → K=8。

因为实验已经说明 report budget 基本救不了最低端。

正确操作应该是：

对每个弱目标 qq，从当前所有可行 Tx-Rx：

(i,j)∈Eq(i,j)\in\mathcal E_q

中计算在 rescue mode 下的实际检测增益：

ΔPD,ijq(m)=PD(Sq∪{(i,j,m)})−PD(Sq).\Delta P_{D,ijq}^{(m)} = P_D \left( \mathcal S_q\cup\{(i,j,m)\} \right) - P_D(\mathcal S_q).

然后比较：

ΔPDenergy/resource cost.\frac{ \Delta P_D }{ \text{energy/resource cost} }.

注意这里不要再只看：

γijq\gamma_{ijq}

或者 singleton Sensing-SINR。

直接使用你现有的：

```
predicted_pd_for_links
```

作为 marginal evaluation 会更一致。

# 五、实际应该形成一个“逐目标救援”算法

可以非常简单，不需要另起炉灶。

### Step 1：所有目标先做标准观测

每个目标先获得一条或者少量最低成本的 local / best observation：

Sq(0).\mathcal S_q^{(0)}.

得到：

P^D,q(0).\widehat P_{D,q}^{(0)}.

------

### Step 2：识别困难目标

定义：

Qweak={q:P^D,q<PDreq}.\mathcal Q_{\rm weak} = \{ q: \widehat P_{D,q}<P_D^{\rm req} \}.

然后按 deficit 排序：

dq=PDreq−P^D,q.d_q=P_D^{\rm req}-\widehat P_{D,q}.

最弱的优先。

------

### Step 3：只给这些目标生成 rescue candidates

不要对 10 个目标全量做：

- 144 looks；
- 1.25 power；
- DD refine。

只对：

q∈Qweakq\in\mathcal Q_{\rm weak}

产生：

(i,j,menhance),(i,j,mrescue).(i,j,m_{\rm enhance}), \qquad (i,j,m_{\rm rescue}).

这样 computational cost 也不会爆。

------

### Step 4：计算每一个 rescue action 的真实边际价值

建议统一成：

V(a∣q)=ΔP^D,q−λEEa−λCCa−λRRa.V(a|q) = \Delta \widehat P_{D,q} - \lambda_E E_a - \lambda_C C_a - \lambda_R R_a.

但**weak target fairness 要在最外层控制**。

所以实际是：

先找当前：

q⋆=arg⁡max⁡qdq,q^\star = \arg\max_q d_q,

再在这个目标内部：

a⋆=arg⁡max⁡a∈Aq⋆V(a∣q⋆).a^\star = \arg\max_{a\in\mathcal A_{q^\star}} V(a|q^\star).

这样比现在所有 target 所有 candidate 混在一起竞争，更适合小 RCS rescue。

# 六、looks 应该成为最重要的“可分配资源”

在当前模型不变的情况下，我认为最值得利用的是：

LqL_q

而不是 power。

因为你已有实验已经证明：

功率 ×100：

≈0.31 dB\approx0.31\ {\rm dB}

而增加 looks：

2.16 dB,2.16\ {\rm dB},

继续到 256：

所以如果保持现有物理模型：

> **时间/观测次数应该是小目标 rescue 的第一算法资源。**

不是所有目标同样 looks。

应该满足一个全局预算：

∑qLq≤Ltotal.\sum_q L_q\le L_{\rm total}.

然后优化：

max⁡{Lq}min⁡qPD,q.\max_{\{L_q\}} \min_q P_{D,q}.

这个问题非常干净。

# 七、power 只作为二级 rescue，不作为第一选择

因为当前模型明显干扰受限：

r=IresidualN0≫1.r=\frac{I_{\rm residual}}{N_0}\gg1.

所以：

γ(mP)=γ(P)m(1+r)1+mr\gamma(mP) = \gamma(P) \frac{m(1+r)}{1+mr}

当 r≫1r\gg1：

γ(mP)≈γ(P).\gamma(mP)\approx\gamma(P).

所以当前已有：

1.25×P1.25\times P

可以保留在 rescue mode 中，但是：

> 不要把 power allocation 当作主优化变量。

操作顺序应该是：

换链路→增加 looks→DD refinement→少量提高 power\boxed{ \text{换链路} \rightarrow \text{增加 looks} \rightarrow \text{DD refinement} \rightarrow \text{少量提高 power} }

而不是反过来。

# 八、DD refinement 应该只服务于“值得救”的链路

C2F 本来就是非常适合这个问题的。

当前不要：

> 所有候选都做 fine DD。

而是：

### coarse stage

先找：

Top-J\text{Top-}J

能够帮助 weak target 的链路。

### fine stage

对 weak target shortlist 使用：

ηfine.\eta_{\rm fine}.

然后重新计算：

γs→LLR moments→P^D.\gamma^s \rightarrow \text{LLR moments} \rightarrow \widehat P_D.

如果 fine processing 不能产生足够：

ΔPD,\Delta P_D,

立即舍弃。

这就是现有 C2F 最合理的定位：

> **不是单纯降计算量，而是把精细处理资源优先给难目标。**

------

# 九、fusion 在这个问题中降级成“保住已经形成的证据”

不要让 fusion 再承担“救小目标”的职责。

因为你的 lossless-report oracle 已经非常清楚：

> 对真正最差目标，transport/fusion headroom 接近 0。

所以 fusion 的任务只剩：

不要把已经辛苦获得的小目标证据弄丢\boxed{ \text{不要把已经辛苦获得的小目标证据弄丢} }

因此：

1. 优先 local observation；
2. 远程 observation 选可靠 reporting leg；
3. 单 fusion 继续保留；
4. exact LLR sum 保留；
5. 不需要再增加两级、多级 fusion。

这个就够了。

我建议下一步只跑一个非常明确的实验链。

固定：

| ----------------- | --------------------------- |
| Fixed             | 所有目标统一普通模式        |

## 最终我建议把“小目标方案”就定成一句话

> **不是依靠更复杂的融合挽救弱回波，而是在现有资源约束下，对检测不足目标触发 selective rescue：优先选择高价值双站观测，动态增加独立 looks，并仅对候选弱链路执行 DD refinement；已满足目标立即停止追加资源，剩余资源按 worst-target detection deficit 重新分配。**

这就已经足够形成一个非常完整的算法逻辑了。

甚至我建议现在**暂时把 17.5 dB hardware gain 从算法主线里拿掉**。先回答一个更有意义的问题：

在完全不增加额外硬件增益时， 现有可控 sensing operations 到底能把 0.05 m2 的 worst-PD 从多少提高到多少？\boxed{ \text{在完全不增加额外硬件增益时， 现有可控 sensing operations 到底能把 }0.05\text{ m}^2 \text{ 的 worst-}P_D \text{ 从多少提高到多少？} }

如果最后比如只能从 0.21 提到 0.79，那么这个 **0.58 的改善本身就是算法贡献**；剩余缺口再诚实解释为物理链路预算边界。这样会比“补 17.5 dB 后做到 0.98”更扎实。
