# 二、目前最严重的第一个问题：融合架构依然没有真正解决

代码已经把部分 reporting 方向改成了 j→ij\to i，这是正确方向；但是 `selection.py` 对同一个 target qq 仍允许选择：

(i1,j1,q),  (i2,j2,q),  (i3,j3,q)(i_1,j_1,q),\; (i_2,j_2,q),\; (i_3,j_3,q)

其中 i1,i2,i3i_1,i_2,i_3 可以完全不同。

然后 `fusion.py` 又把这些统计量放到同一个集合里直接计算：

Fq=∑ℓwℓqsℓq.F_q=\sum_\ell w_{\ell q}s_{\ell q}.

这就产生一个物理问题：

**这些 soft statistics 到底在哪里相遇？**

如果规定 j→ij\rightarrow i，那么第一条数据去了 i1i_1，第二条去了 i2i_2，第三条去了 i3i_3。代码最后却默认它们已经在同一个 fusion node。

因此 Reviewer 1/2/3 对 fusion architecture 的批评，**目前实际上仍然成立**。

### 我建议彻底改成下面这个结构

引入明确的 target-specific fusion UAV：

fq∈M.f_q\in\mathcal M.

感知链路继续定义为

(i,j,q):i→q→j,(i,j,q): \quad i\rightarrow q\rightarrow j,

但是报告链路彻底与 sensing pair 解耦：

j→fq.j\rightarrow f_q.

于是 triplet 的价值变成：

(i,j,q;fq).(i,j,q;f_q).

其通信可靠性、时延应该全部采用

χjfq,Rjfq,Tjfq,\chi_{j f_q},\qquad R_{j f_q},\qquad T_{j f_q},

而不是 χij\chi_{ij}。

这与近年的 networked sensing 文献思路也是一致的。例如 2024 TCOM 的 **“Power Optimization for Integrated Active and Passive Sensing in DFRC Systems”** 明确区分 sensing nodes、backhaul 和 central controller，并针对有限/无限 backhaul 采用不同 fusion strategy。([IEEE Xplore](https://ieeexplore.ieee.org/document/10440313/?utm_source=chatgpt.com))

这里正好可以直接借用它的**架构模块**，而不是仅引用标题。

# 三、第二个核心问题：χ=γ/(γ+γreq)\chi=\gamma/(\gamma+\gamma_{\rm req}) 仍然没有理论依据

这是三个 reviewer 都直接或间接指出的问题。

现在论文仍然写：

χij=γijcγijc+γreq.\chi_{ij} = \frac{\gamma_{ij}^{c}} {\gamma_{ij}^{c}+\gamma_{\rm req}}.

这只能说是一个平滑 monotonic mapping，但不能自然解释成“packet success probability”。

这也是当前模型中最应该删除的 heuristic 之一。

## 应改成 finite-blocklength packet reliability

soft information 本质上是短控制/感知报告包，因此非常适合直接引入 FBL：

ϵab≃Q(C(γab)−knV(γab)/n),\epsilon_{ab} \simeq Q\left( \frac{ C(\gamma_{ab})-\frac{k}{n} }{ \sqrt{V(\gamma_{ab})/n} } \right),

其中

C(γ)=log⁡2(1+γ),C(\gamma)=\log_2(1+\gamma),V(γ)=(1−1(1+γ)2)(log⁡2e)2.V(\gamma) = \left(1-\frac{1}{(1+\gamma)^2}\right)(\log_2 e)^2.

然后定义

χab=1−ϵab\boxed{ \chi_{ab}=1-\epsilon_{ab} }

就可以了。

这样：

- reliability 有明确概率意义；
- packet bits kk 真正影响 reliability；
- blocklength nn 同时决定 latency；
- reliability、payload 和 latency 不再是三个独立手调量。

2024 TWC 的 **“Mobile Edge Computing Aided Integrated Sensing and Communication With Short-Packet Transmissions”** 已经明确把短包可靠性、时延和 sensing data transmission 放在同一体系里。([IEEE Xplore](https://ieeexplore.ieee.org/document/10375321/?utm_source=chatgpt.com))

2024 年 **“Integrated Sensing and Communication in the Finite Blocklength Regime”** 更进一步，从 rate–distortion–error 的 finite-blocklength 区域给出了理论框架。([arXiv](https://arxiv.org/abs/2401.15752?utm_source=chatgpt.com))

到 2026 年的 **“Fundamental Tradeoffs for ISAC Multiple Access in Finite-Blocklength Regime”** 又进一步研究了 blocklength、codebook correlation 和 sensing accuracy 的耦合。([arXiv](https://arxiv.org/abs/2601.05165?utm_source=chatgpt.com))

### 所以这里可以形成一个很干净的升级

现在：

γc→χheuristic→μeff,σeff\gamma_c \rightarrow \chi_{\rm heuristic} \rightarrow \mu^{eff},\sigma^{eff}

升级为：

γc,n,k→ϵFBL→χ=1−ϵ→reported LLR distribution.\gamma_c,n,k \rightarrow \epsilon_{\rm FBL} \rightarrow \chi=1-\epsilon \rightarrow \text{reported LLR distribution}.

这会一次性解决 Reviewer 1–3 对通信可靠性的质疑。

# 十一、当前 fusion 还忽略了一个越来越重要的问题：观测相关性

现在 composite deflection 基本仍采用：

D=(∑wiμi)2∑wi2σi2.D = \frac{(\sum w_i\mu_i)^2} {\sum w_i^2\sigma_i^2}.

它隐含：

Cov⁡(sa,sb)=0,a≠b.\operatorname{Cov}(s_a,s_b)=0, \qquad a\neq b.

但你的 UAV cooperative sensing 明显不满足这个条件：

- 多个 bistatic pair 共享 transmitter；
- 共享 receiver；
- 共享 target fluctuation；
- 共享 interference；
- 可能落在相邻 DD support；
- 同一个目标产生相关 echo。

真正应该写成：

Dq(S)=(wTδq)2wTΣqw.D_q(\mathcal S) = \frac{ (\mathbf w^T\boldsymbol\delta_q)^2 }{ \mathbf w^T \mathbf\Sigma_q \mathbf w }.

最优 linear fusion：

wq⋆∝Σq−1δq\boxed{ \mathbf w_q^\star \propto \mathbf\Sigma_q^{-1} \boldsymbol\delta_q }

于是：

Dq⋆=δqTΣq−1δq.D_q^\star = \boldsymbol\delta_q^T \mathbf\Sigma_q^{-1} \boldsymbol\delta_q.

这会产生一个非常漂亮的效果：

> **相关、冗余的 UAV observations 会被数学上自动降权。**

这样你现在很多人为的 geometric diversity factor、重复观测 penalty 都可以删掉。

2025 年 **“Collaborative Design for Moving Target Detection in Distributed Radar Networks”** 就非常值得跨学科借鉴：它明确把 **echo correlation + communication burden + network topology** 一起建模，并设计 coherent / noncoherent / hybrid collaboration，还根据 observation correlation 与 communication cost 做 clustering。([ResearchGate](https://www.researchgate.net/publication/398712397_Collaborative_design_for_moving_target_detection_in_distributed_radar_networks?utm_source=chatgpt.com))

# 十二、当前 greedy 最大的问题不是“算法不够复杂”，而是没有可证明结构

实现本身没有问题。

问题是 reviewer 会问：

> 为什么 greedy？

当前增加的小规模 oracle 是有帮助的，但它优化的是更简单的 detection objective，而不完全等于实际 greedy 的：

αqΔD−λc.\alpha_q\Delta D-\lambda c.

## 我更推荐把理论往 submodular selection 拉

如果 local observations 条件独立，信息目标可以写成：

Jq(S)=∑ℓ∈SJℓq,J_q(S) = \sum_{\ell\in S}J_{\ell q},

属于 modular。

考虑 diminishing returns / information covariance 后，可以设计：

Fq(S)=log⁡det⁡(I+∑ℓ∈SAℓq),F_q(S) = \log\det \left( I+ \sum_{\ell\in S}A_{\ell q} \right),

这一类信息函数通常具有良好的 monotone/submodular 结构。

于是问题变成：

max⁡SF(S)\max_{S} F(S)

subject to

∑ℓ∈Sbℓ≤Bmax⁡,\sum_{\ell\in S}b_\ell\le B_{\max},T(S)≤Tmax⁡,T(S)\le T_{\max},∣Sq∣≤Lq.|S_q|\le L_q.

这就不是：

> “我们觉得 greedy 快，所以用了 greedy”

而是：

> “目标具有 diminishing-return structure，因此使用 cost-aware greedy，并给出 approximation guarantee。”

这对论文档次的提升非常明显。

# 十三、现在 reporting delay 模型也必须统一

Reviewer 2 特别问了：

> selected links 是 sequential reporting 还是 parallel reporting？

目前实现的 aggregate delay 基本是：

Treport=∑ℓ∈SBℓRℓ,T_{\rm report} = \sum_{\ell\in S} \frac{B_\ell}{R_\ell},

即**串行发送**。

但是 active-set communication interference 又在某些配置里把 selected reporters 视为**同时活动**。

于是模型实际上出现：

SINR：parallel\text{SINR：parallel}

但

latency：serial.\text{latency：serial}.

这是不自洽的。

建议下一版不要再留模糊空间，直接选一个 MAC model。

最合理的是 slot/conflict scheduling：

S=⋃r=1RS(r)\mathcal S = \bigcup_{r=1}^{R} \mathcal S^{(r)}

其中同一 slot 内可以并发。

然后：

Ttotal=∑rTr,T_{\rm total} = \sum_r T_r,Tr=max⁡ℓ∈S(r)nℓRs.T_r = \max_{\ell\in\mathcal S^{(r)}} \frac{n_\ell}{R_s}.

且通信 SINR 只计算同一：

S(r)\mathcal S^{(r)}

里的 co-channel reporters。

这样 interference 和 delay 才终于是一个系统。

# 十七、具体到 `hy_cg`，我建议按这个顺序改，而不是继续增加新功能

唯一建议的实施优先级如下：

1. **P0：先重建 system identity。** 明确 i→q→ji\to q\to j 与 j→fqj\to f_q，引入显式 fusion UAV/FC；同步修改 `SystemModel.tex`、`model.py`、`selection.py`、`fusion.py`。这是所有后续工作的基础。
2. **P0：删除 heuristic reliability。** 用 FBL PER 得到 χ=1−ϵ\chi=1-\epsilon，同时统一 bits、blocklength、reliability 和 latency。
3. **P0：拆开 truth 与 belief。** `prior.py` 不再修改“真实环境”，而是产生 (x^,P)(\hat x,P)；selection 只能访问 belief，waveform/detection 访问 truth。随后做 position/velocity uncertainty sweep。
4. **P1：把 soft statistic 变成 waveform-derived LLR。** 不再使用 κμlog⁡(1+γs)\kappa_\mu\log(1+\gamma_s)。先从 matched-filter/local-energy detector 做起，没必要一步上复杂 ML。
5. **P1：融合升级为 covariance-aware。** 使用 δTΣ−1δ\delta^T\Sigma^{-1}\delta 或 KLD，建立 observation correlation 与 link redundancy 的理论关系。
6. **P1：重构优化问题。** 目标统一成 task information–communication cost；小规模 oracle 必须与 greedy 优化**同一个 objective**。进一步证明 submodularity / approximate-submodularity / curvature，而不是仅做经验 greedy。
7. **P1：重做 C2F。** coarse estimator 和 fine estimator 都映射到真实 OTFS spectrum/PSF；κdd\kappa_{dd} 和 ηmin⁡\eta_{\min} 最终应删除或退化为 waveform-calibrated quantity。
8. **P2：统一 reporting MAC。** 明确 TDMA、FDMA 或 conflict-slot scheduling。不要再出现 concurrent SINR + serial delay。
9. **P2：重新做实验。** 必须补 `belief mismatch`、FBL/blocklength、correlation ablation、same-physics C2F vs full refinement、same-physics all-neighbor、same-objective oracle gap、runtime，以及 trial-level bootstrap CI。

## 最终判断

如果问题是：

> “当前这个版本能不能认为 ISAC 2026 审稿问题已经修好了？”

我的答案是：**不能。**

当前版本真正解决的是：

- 代码结构和 reproducibility；
- ηloc\eta^{loc} 的明确计算；
- C2F 的实际执行 bug；
- Top-K Deflection 等 baseline；
- CI 输出框架；
- 小规模 waveform kernel / oracle / runtime 的基础设施。

但是真正决定下一次审稿结果的几个问题仍然在：

fusion architecture\boxed{ \text{fusion architecture} }probabilistic reporting reliability\boxed{ \text{probabilistic reporting reliability} }true state vs belief\boxed{ \text{true state vs belief} }physical soft statistic\boxed{ \text{physical soft statistic} }correlated fusion\boxed{ \text{correlated fusion} }optimization/greedy theory\boxed{ \text{optimization/greedy theory} }

尤其不要继续在现在的 β,α,κ,ηmin⁡,μα\beta,\alpha,\kappa,\eta_{\min},\mu_{\alpha} 上做更多 sweep。**当前最该做的不是“参数优化”，而是删除一部分经验参数，用可推导的物理/统计量替代它们。**

如果按这个方向重构，`hy_cg` 才会从目前偏“工程型 communication-aware greedy scheduler”，真正转成一个更像 **TWC/TSP 风格的通信受限协同检测理论模型**。
